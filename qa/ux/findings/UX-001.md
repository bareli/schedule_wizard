## Problem

The editor offers **Repeat: Every N days**, a count and a field **Starting on** (de: "Ab dem", he: "החל מתאריך"). The field defaults to **today**. Nothing says that this is the day of the first watering, or what happens when today's time has already passed.

Reproduced at 11:08 on 2026-10-01: Add time on a zone, Repeat = Every N days, N = 2, time 06:00, start date left on today (01/10/2026), Save. The week view now shows a greyed 06:00 chip under **Today** (looks like a run that already happened; it never did, the schedule did not exist at 06:00) and the real first run is **Saturday 06:00**, two days away. A gardener who adds "every other day" in the late morning and leaves the defaults expects tomorrow, gets Saturday, and is only told by the Home card ("Next: ... Sat 6:00 AM"), which they have to go and look at. The save toast is just "Done".

Smaller points on the same field: it is the browser's native date control, so it shows `01/10/2026` while the list reads "Oct 1, 2026" in the HA locale (1 Oct or 10 Jan is not obvious to a US or German reader); the list row ("Every 2 days from Oct 1, 2026 at 06:00") says "from", the editor says "Starting on", and neither says "first watering".

## Why it matters

johnpower asked for "every other day". The feature is findable (Repeat is the second field, one select) and N defaults to 2, so the task is quick. The risk is the second half: the start date IS the schedule's phase, and a wrong phase means the plants wait a day longer than planned with no signal at save time. Garden owners do not read the week view after saving.

## Recommendation

1. Rename the label to **First watering on** (de: "Erste Bewässerung am", he: "ההשקיה הראשונה בתאריך").
2. Under the two fields, a live line computed from time + start date + N: "First run: Sat, Oct 3 at 06:00, then every 2 days" (all 17 languages via the existing date formatter). When the start date is today and the time has passed, say so: "Today's 06:00 has passed, first run is Sat, Oct 3."
3. Optionally default the start date to tomorrow when the chosen time is already past.
4. Do not render a greyed chip for a run slot that predates the schedule's creation (week view).
