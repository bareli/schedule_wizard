## Problem

1. "Skip watering when it rains, using" is a free-text box with the placeholder "weather.home or sensor.rain_forecast". The zone pickers elsewhere are searchable lists; this one must be typed from memory.
2. Typing `banana` and pressing Save settings shows "Saved at 1:01:34 PM." in the panel with no warning. The product does detect it (a Repair "missing_rain_entity_banana" appeared and raised the HA Settings badge from 2 to 3) but only in HA's Repairs screen, not where the user typed it. Clearing the box removed the repair.
3. Once an entity is chosen, what counts as rain lives in More options > Rain details (comma-separated states "rainy,pouring,snowy,lightning-rainy", attribute, numeric threshold), a second place for one decision.
4. "Send notifications to" lists raw service names: `persistent_notification` and `send_message`. A gardener cannot tell what "send_message" reaches; mobile_app targets would read `mobile_app_pixel_8`.

## Why it matters

"Skip when it rained" is one of the three jobs a gardener came for. A typo is accepted silently and the garden gets watered in the rain while the panel said Saved.

## Evidence

![Rain source 'banana' accepted: Saved at 1:01:34 PM, no warning](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/UX-011-rain-entity-free-text-banana-saved.png?raw=1)

## Recommendation

Entity picker limited to weather.* and sensor.* with a "none" option; inline warning under the field when the entity does not exist (reuse the repair text); show the default rain states as a one-line sentence under the picker; friendly names for notify targets ("Phone: Pixel 8", "HA notifications panel"). Wording and picker design are product calls (model:opus).

## Kind

Works, could be better (point 2 is a silent-failure risk, so the strongest of the four).

Offered in the report.

## Handback (qa-developer, 2026-10-01): UX-011

Owner ruling: implement the record's recommendation.

**Fix** (`a50e935`, `www/panel.js` `_rainPicker` / `_notifyLabel`, `__init__.py`, `scheduler.py`):
1. **Picker**: "Skip watering when it rains, using" is a list: Don't check for rain, then Weather, Rain sensors (precipitation / moisture device class or a rain word in id or name), Other sensors (`weather`, `sensor`, `binary_sensor`), each "Name (entity_id)".
2. **Inline check** under it, live: "Skips when the state is rainy, pouring, snowy, lightning-rainy. Now: rainy. That counts as rain: watering would be skipped now." (threshold: "Skips at 2 or more. Now: 0.4."; binary sensor: "Skips while the sensor is on."). A saved source that no longer exists stays selected as "weather.home (not found)" with a red "does not exist in Home Assistant. Rain skip is off until it does." Server: `update_options` refuses a new `rain_entity` that does not exist or is not weather/sensor/binary_sensor (an unchanged missing one still saves; it keeps its repair); the error lands under the field. Rain details (states, attribute, threshold) stay in More options; the check line follows them as they are typed.
3. A `binary_sensor` rain source counts as rain while `on` (it can now be picked; before it never skipped).
4. **Notify targets** by what they reach: "Phone: Pixel 8" (mobile_app device name), "Home Assistant notifications", "Notification entities", "Default notifier", other services humanised; the service name stays in the tooltip. get_state adds `notify_targets_info`.

## Handback, second pass (qa-developer, 2026-10-01): UX-011 check line for binary sensors

**What the first pass missed** (verifier's point 1): `_rainPicker` used the binary wording only when the states list was empty, and the default list never is.

**Fix** (`9c03ee5`, `www/panel.js` new `rainCheckParts()`): the line now says the rule the server applies (`scheduler._should_skip_for_rain`) to *this* source:
- `binary_sensor.*`: "Skips while the sensor is on. Now: off." whatever the states list holds (he "מדלג כשהחיישן פעיל. כעת: off.").
- A threshold is shown only when there is a number to compare (the value, or the attribute): "Skips at 2 or more. Now: 0.4." (with an attribute, "Now" is the attribute value). A weather word is never compared with the threshold (the server falls back to the states list), so "Skips when the state is rainy, ... Now: sunny."
- A sensor that reports a number while no threshold is set: the states line plus "A number never matches these states: set a numeric threshold under More options > Rain details." (new key `set.rain_check_numeric`, 17 languages).
- The "own sensors in Other sensors" remark is filed and fixed as #91.
