## Problem

With the temperature adjustment at 0 %, History reads `ENG front: skipped (temperature 0 %)`, the zone card reads `Last: 29 s ago * 10 min * skipped (Temperature 0 %)` and the notification setting reads `Skipped (temperature 0 %)`. Three problems:

1. "temperature 0 %" mixes a quantity with a percent sign. It reads as "the temperature is 0 percent". The thing that is 0 % is the **watering adjustment**, and the cause is that it is **too cool**. johnpower understood it only because he had just configured Min % = 0.
2. The actual notification text sent by the integration (scheduler.py SKIP_TEXT) says `Skipped ENG front: temperature adjustment 0 %`: different wording for the same event, and **English only** in German and Hebrew installs (the reminder texts are translated, skip texts are not).
3. The zone card line keeps the planned duration ("10 min") next to "skipped", which reads like the zone ran 10 minutes and was then skipped.

## Why it matters

The brief's question: does the user understand why nothing watered? Only if they already know the feature. A garden owner on a cool morning who gets "Skipped ENG front: temperature adjustment 0 %" (in English, on a German phone) cannot tell if a sensor broke, the weather was cold, or something is misconfigured, and the natural reaction is to file a bug or press Water now. The notification was verified from source (scheduler.py `_record_skip`), no notify target is configured on the dev instance.

## Recommendation

Pick one phrase for history, event and notification, naming cause and effect, for example: **"skipped: too cool, adjustment 0 %"** / de "übersprungen: zu kühl, Anpassung 0 %" / he "דולג: קריר מדי, התאמה 0%". Translate the notification body like the reminders. Hide the planned minutes on skipped rows or label them "planned". Product call on wording, so model:opus.
