## Problem

With tomorrow's forecast 36 °C / 1 °C / 8 mm / 80 %, the Home tab offers three tips for the **same single run** (Herb bed, Sat 7:00 AM, 5 min):

1. Heat: "+30 % tomorrow" (already applied by another tester: banner "Watering +30 % on Sat 10/10.", week shows "5 min → 7 min"),
2. Rain: "Consider skipping Herb bed. Saves about 20 L (5 min)",
3. Frost: "Consider skipping the early runs: Herb bed. Saves about 20 L (5 min)".

The tips do not know about each other: after "water more" was accepted the card still says "skip", the savings still use the unboosted 5 min / 20 L while the run dialog says "Expected: 7 min, About 28 L", and the two skip tips together suggest 40 L saved for one 20 L run. Nothing tells the gardener which to follow. Stacked, the card is about 320 px tall above "Your zones" and pushes the zones below the fold on a laptop.

## Why it matters

The core job is "skip tomorrow because of rain". A hot day with an afternoon storm is ordinary in summer (and in Israel in spring); contradictory advice teaches the user to ignore the card.

## Evidence

![Boost banner, rain and frost tips for the same run, week shows 5 min to 7 min](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/UX-022-tips-and-boost-en-1440.png?raw=1)

## Recommendation

One recommendation per day, priority rain > frost > heat:
- If a rain tip covers a run, drop the heat tip for that day and drop frost runs already covered by rain. If both remain, merge: title "Tomorrow: 8.0 mm rain, frost down to 1 °C", text "Consider skipping Herb bed.", button "Skip tomorrow".
- If a boost is already set for that day, the rain tip says so: "You set +30 % for tomorrow, but 8.0 mm rain is expected. Skip Herb bed instead?" Buttons "Skip tomorrow" (also cancels that day's boost) / "Not now".
- Compute "Saves about ..." from the expected (boosted, temperature-adjusted) minutes, the same number the run dialog shows.
- More than 2 tips: show the first two and "1 more tip" disclosure.

## Verification (qa-ux-expert, verifier mode, 2026-10-09, dev 8181 @ 2ada640, panel.js contains _goToSetting, cache disabled)

Status: REOPENED (core fix works; two residues)
- OK: forecast 36/1/8 mm/80 %: ONE tip "tomorrow: 8.0 mm rain, frost down to 1 °C", no heat tip, no separate frost tip, "Consider skipping Herb bed." (no boost: 5 min, 20 L).
- OK: with +30 % set for Sat: "You set +30 % for tomorrow, but rain is expected. Skip Herb bed instead?"; "Skip tomorrow" ended the boost (boost = {}) and skipped the run; undone afterwards, boost restored.
- OK: more than 2 tips shows first two plus a disclosure (3 tips injected in the panel state).
- RESIDUE 1: "Saves about 26 L (6 min)" but the run dialog and week say Expected 7 min / 28 L. Backend `planner.scale_pct` uses Python round (6.5 -> 6), the panel uses Math.round (6.5 -> 7). Same number is required; use one rounding.
- RESIDUE 2: the disclosure with 3 tips reads "1 more tips" (en) / "1 weitere Tipps" (de). `tips.more_one` exists in i18n.js but panel.js `_tipsCard` calls `_tn("tips.more")` with no singular branch.
- Minor: title begins lowercase ("tomorrow: ...", "morgen: ...", "מחר: ..."), because `tips.tomorrow` is a lowercase sentence word reused as a title prefix.
Evidence: qa/evidence/UX-022-tips-merged-after.png, UX-022-after-skip-after.png

## Residue fix (2026-10-09, after REOPENED)

- Savings rounding: `planner.scale_pct` now rounds half up like the panel's `Math.round` (5 min x 130 % = 7, not 6). Unit test `test_minutes_round_half_up_like_the_panel`.
- "1 more tips": the disclosure now uses `_t("tips.more", {n})`, which picks `tips.more_one` for 1.
- Merged rain/frost title starts with a capital ("Tomorrow: ...").
