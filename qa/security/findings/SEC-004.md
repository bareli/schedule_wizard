## Summary

SECURITY RISK, reasoned from code plus one reproduced request; not flood-tested (no load testing). Each webhook run, even for a non-existent entity, records started and cancelled rows, with no rate limit. History is capped at 500 and trimmed oldest first, so a few hundred requests evict genuine run history used by reports and the Settings history. Disk growth is bounded by the cap.

## Steps to reproduce

One POST webhook {"entity_id":"switch.does_not_exist","duration_minutes":1} -> 200. Admin get_state history then held started and cancelled rows (source webhook) for that entity. Roughly 250 such calls would evict every earlier row (not performed).

## Expected

Unknown entities rejected before any history write.

## Actual

History rows written for entities that do not exist.

## Relevant files

storage.py:14 and 400-407; scheduler.py async_run_valve; __init__.py webhook handler.

## Fix prompt

Largely resolved by SEC-001. Also skip history for runs whose entity has no state, and ignore a repeated webhook run for the same entity within 2 seconds. Test: non-existent entity writes no history row.

Evidence: request and response text above. Redacted: webhook id (shown as WEBHOOK_ID) and access tokens (never recorded). Screenshot: Evidence unavailable, not an interface defect.

## Handback: SEC-004 (#37)

**Fix:** the webhook rejects an entity that is not a registered zone (see #34). For `run` it also rejects a registered zone whose entity has no state in HA. Both checks happen before `async_run_valve`, so no `started` or `cancelled` history rows are written. I did not add the suggested 2-second de-duplication of repeated runs. With the zone restriction, a flood can only re-run real zones, and each re-run replaces the previous one with a `superseded` row. I left it out of scope; it can be filed separately if wanted.

**Verification recipe:**
- Account: none for the POSTs. qa_admin for `get_state`.
- URL: `POST http://127.0.0.1:8170/api/webhook/WEBHOOK_ID`.
- Expect:
  1. `{"entity_id":"switch.does_not_exist","duration_minutes":1}` gives `404 {"error": "unknown zone"}`, and admin `get_state` `history` has no row for `switch.does_not_exist`.
  2. Register a zone for an entity that does not exist (`schedule_wizard.add_valve` with entity_id `switch.gone`, label `Gone`). `{"entity_id":"switch.gone","duration_minutes":1}` then gives 404, with no history row and no active run. Clean up with `schedule_wizard.remove_valve` for `switch.gone`.

- Test: `tests/test_security.py::test_webhook_rejects_missing_entity_without_history` failed at baseline (status 200) and passes after the fix.
