## Summary

HA lets any authenticated user call services. add_valve, add_schedule and add_cycle take cv.string labels and names of any length and any number of rows, all stored in .storage and returned by every get_state. Reproduced: a non-admin stored a 200000-char label (then removed it). Source-reasoned: _on_notification_action passes the day string from a mobile_app_notification_action event to async_add_skip unvalidated; prune compares strings, so a junk day is never pruned, and unskip (cv.date) cannot remove it (not fired, to avoid leaving junk). The history CSV export (panel.js:2669) does not neutralise cells starting with = + - @, so a label such as =HYPERLINK(...) becomes a spreadsheet formula when the owner opens the file. Stored XSS: none found.

## Steps to reproduce

As qa_user: call_service schedule_wizard.add_valve {entity_id: light.qa_sec_probe, label: 200000 x "A", enabled: false} -> success; get_state returned the 200000-char label; remove_valve -> success (cleanup done).

## Expected

Label/name length limit (for example 80), caps on valves, schedules and cycles (for example 200), day validated as YYYY-MM-DD, CSV formula guard.

## Actual

No limits; CSV formula cells unescaped.

## Relevant files

__init__.py SCHEMA_ADD_VALVE / ADD_SCHEDULE / ADD_CYCLE; scheduler.py:426-441; storage.py:113 and 127-138; www/panel.js:2669.

## Fix prompt

Add vol.Length(max=80) on label and name in the service schemas, caps in storage add_*, date.fromisoformat check in _on_notification_action, apostrophe prefix for CSV cells starting with = + - @. Tests for each; existing longer stored labels must still load.
