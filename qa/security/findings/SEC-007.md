## Summary

update_options (admin only, so no privilege is crossed) takes master_valve_entity as any string; the scheduler derives the service domain from the entity id and calls <domain>.turn_on / turn_off. Reproduced: script.qa_not_a_valve was accepted (then reset). A script, automation or climate id would be turned on and off around every run. Webhook and services validate the domain; this is the one actuating setting that does not. Rain, moisture, flow, forecast and temperature entity strings are only read. Notify targets are only called under the notify domain.

## Steps to reproduce

As qa_admin: WS schedule_wizard/update_options {master_valve_entity: "script.qa_not_a_valve"} -> success true; reset to null afterwards. Execution not triggered.

## Expected

master_valve_entity limited to SUPPORTED_DOMAINS or empty.

## Actual

Accepted.

## Relevant files

__init__.py:568; scheduler.py:1685-1725.

## Fix prompt

Use vol.Any(None, '', _entity_in_supported_domain) for master_valve_entity in _ws_update_options and re-check in scheduler._async_master_open. Test: script.x rejected, valve.x accepted, null clears.

## Handback: SEC-007 (#40)

**Fix:**
- **Server, `schedule_wizard/update_options`.** `master_valve_entity` now goes through the schema `vol.Any(None, "", _entity_in_supported_domain)`, so it must be a valid entity id in switch, valve, cover, input_boolean or light. A value that differs from the stored one must also exist in `hass.states`, otherwise the error is `invalid_format` "main valve X not found". An unchanged value whose entity has since disappeared is still accepted, so a missing pump does not lock the admin out of saving Settings.
- **Runtime.** `_build_options` ignores a stored master valve of another domain (it treats it as empty and logs a warning). A `script.*` saved before this fix is no longer turned on and off around runs. The stored entry options are not rewritten.
- **Panel, Settings → More options → Main valve.** Save is blocked with an inline error under the field ("X is not a switch, valve, light, cover or input_boolean in Home Assistant.", 17 languages) plus an error toast. The check accepts the entities in the `controllable` list, which means supported domain and existing. The field also re-checks on change.
- **Options flow (Configure dialog).** It has no master valve field and merges the stored value unchanged, so there was nothing to validate there.
