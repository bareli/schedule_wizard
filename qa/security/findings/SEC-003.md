## Summary

The handler assumes the JSON body is an object and action a string. Otherwise the exception reaches the catch-all, which logs a traceback and returns str(e) to the caller. Disclosure is small (Python attribute error text) but it is unauthenticated and logs a traceback per request.

## Steps to reproduce

POST /api/webhook/WEBHOOK_ID:
- body [1,2] -> 500 {"error":"'list' object has no attribute 'get'"}
- body "abc" (JSON string) -> 500 {"error":"'str' object has no attribute 'get'"}
- body {"entity_id":"input_boolean.zone_front","action":123} -> 500 {"error":"'int' object has no attribute 'strip'"}

## Expected

400 invalid payload for wrong shapes; the catch-all returns a fixed message.

## Actual

500 with raw exception message.

## Relevant files

__init__.py:625-652.

## Fix prompt

After parsing require isinstance(payload, dict) and isinstance(action, str), else 400 {error: invalid payload}. Replace str(e) in the catch-all with a fixed 'internal error' (keep LOG.exception). Tests: list, str, int action -> 400; valid run and stop still 200.

Evidence: request and response text above. Redacted: webhook id (shown as WEBHOOK_ID) and access tokens (never recorded). Screenshot: Evidence unavailable, not an interface defect.

## Handback: SEC-003 (#36)

**Fix:** `_webhook_handler` now rejects a body that is not a JSON object with `400 {"error":"invalid payload"}`. An `action` that is not the string `run` or `stop` gets `400 {"error":"action must be run or stop"}`. A bad `entity_id` gets `400 {"error":"invalid entity_id"}`. A duration that overflows when converted to an integer gets the existing 400. The catch-all still logs the traceback (`LOG.exception`), but it now returns `500 {"error":"internal error"}` instead of `str(e)`.

**Verification recipe:**
- Account: none for the POSTs. Register `input_boolean.zone_front` as a zone first, so that the action and entity checks are reached.
- URL: `POST http://127.0.0.1:8170/api/webhook/WEBHOOK_ID` with `Content-Type: application/json`.
- Expect:
  - Body `[1,2]` gives `400 {"error": "invalid payload"}`.
  - Body `"abc"` gives `400 {"error": "invalid payload"}`.
  - `{"entity_id":"input_boolean.zone_front","action":123}` gives `400 {"error": "action must be run or stop"}`.
  - `{"entity_id":"input_boolean.zone_front","action":"explode"}` gives 400, and zone_front stays off.
  - `{"entity_id":"climate.x"}` gives `400 {"error": "invalid entity_id"}`.
  - Valid run and stop of zone_front still give 200.
  - None of the responses contain `object has no attribute`, and the HA log has no traceback for these requests.
- Before (baseline e30fa88): the first three returned `500 {"error":"'list' object has no attribute 'get'"}`, `500 {"error":"'str' object has no attribute 'get'"}` and `500 {"error":"'int' object has no attribute 'strip'"}`. `"explode"` ran the zone.
- The generic 500 cannot be triggered from outside without a fault. It is covered by `tests/test_security.py::test_webhook_internal_error_is_generic`, which failed at baseline because the response contained the exception text, and passes after the fix.
