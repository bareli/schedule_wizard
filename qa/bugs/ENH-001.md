## Problem

The only place that says "this will be skipped" is the live preview inside Settings > More options > Water more when it's hot ("Current: 5C -> factor 0% -> scheduled watering is skipped"). Home, the week view and the zone cards list those runs as normal watering ("Next: ... 10 min", chips "11:08 ENG front 10 min"). Manual skips get a "Skipped" tag in the week view; a run that the temperature factor will skip does not. In the evidence, the 11:08 chip of ENG front is shown as an ordinary run although History shows it was skipped at 11:08. A user who looks at Home before a cool morning sees a plan that will not happen, and a user who looks after sees an ordinary chip for a run that did not.

Two related reading points: the Min % field and the help text never say that 0 means skip (only the preview does), and there is a cliff between 0 % (skip) and 1 to 3 % (the preview reads "factor 3% -> 10 min would run 1 min").

## Why it matters

The 0 % behaviour was requested because plants should not be watered in the cold, so users will rely on it. The status they check first (Home) should not contradict it.

The 0 % state in the second image was produced by typing 0 into Min % without saving, so the shared QA temperature entity was not touched.

## Recommendation

1. Status card on Home: when the current factor is 0 %, replace "All good" with a badge "Cool: runs skipped (0 %)" and show the factor (e.g. 78 %) whenever it is not 100 %.
2. Week view: tag today's and tomorrow's chips "will be skipped (cool)" while the factor is 0, using the same tag style as manual skips; tag past chips "skipped" from history.
3. Settings: add "0 = no watering" to the Min % hint and to seasonal_p5.
4. Product call: should a very low factor (1 to 5 %) also skip, instead of running 1 minute?
