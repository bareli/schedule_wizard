## Summary

`set_override` for today only checks that the NEW time is in the future. It accepts a new time for a schedule whose run today has already happened, and the cron loop then fires it again at the new time. The panel hides "This time only" for past runs, but the service (Dev Tools, automations, any signed-in user) allows it.

## Steps to reproduce

1. Schedule "Trees deep" (169bf5ada2b3, input_boolean.zone_drip, 05:00, 45 min) ran today 05:00-05:45 (history: completed, 270 L).
2. At 05:38: `schedule_wizard.set_override {"schedule_id":"169bf5ada2b3","date":"2026-10-09","time":"06:00","percent":25}` -> success.
3. Wait for 06:00.

## Expected

Refused ("today's run has already happened"), like a passed new time is refused.

## Actual

06:00:00 `input_boolean.zone_drip off -> on`, `schedule_wizard_valve_started` duration 14, note `schedule:169bf5ada2b3|boost:130%|once:25%@06:00`. Zone watered twice today. The week view also drops the 05:00 run that happened.

## Likely root cause

__init__.py `_svc_set_override`: for `day == today` also refuse when `planner.fire_at(sched, day)` (the original time, or an existing override time) is already <= now.
