Declared standard: none in `qa/PROJECT.md`, WCAG 2.1 AA assumed. Tooling: Chromium 153 + Playwright 1.63.0 (accessibility tree). **No real screen reader was available.**

## Summary

The "Last 30 days: total minutes per day" chart is 30 `<div>` bars whose value exists only in a mouse `title` tooltip: no role, no name, not focusable, no text equivalent. The per-zone and per-plan "tables" are CSS grids of `<span>`s, so column headers are not associated with cells.

## Steps to reproduce

1. Home, Reports (one watering run in the last 30 days).
2. Read the accessibility tree of the tab panel; count `<table>` and `role=img` elements; Tab through the chart.

## Expected

The chart has a text alternative carrying the same information (or a data table), tables use table semantics. Source: WCAG 1.1.1, 1.3.1.

## Actual

Tree for the chart: only `heading "Last 30 days: total minutes per day"` and the text `9/2 9/17 10/1`; no bar and no value. 0 `<table>`, 0 `role=img`. Zone table reads as the flat text "Zone 7d 30d Total Front lawn 1x / 10 min 1x / 10 min ..." with no header relation. Partial mitigation: 7 d, 30 d and total per zone appear in the grid, but the per-day distribution exists only in the chart.

## Evidence

![reports view: chart bars and div-grid tables](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/BUG-009-reports-chart-no-text-alternative.png?raw=1)

Desktop 1280x900, light theme, English. The single bar (10/1) has no value, label or keyboard access; the tables below are visually aligned only by CSS grid. Code: `panel.js` L2548-2557 (chart, `title` only), L2566-2621 (grid tables).

## Likely root cause

Chart and tables are built from generic divs and spans. Likely.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` (`_renderReports`).

## Recommended remediation

Give the chart `role="img"` with an `aria-label` summarising total and peak days, and provide the daily values in a visually available or collapsible `<table>`; convert the per-zone, per-plan tables to `<table>` / `<th scope>` (or ARIA grid roles). Product call on how much text to expose, hence model:opus.

## Regression test

A11Y-08: accessibility-tree check on the Reports view (chart named; tables expose headers). A pytest test cannot render the page.

## Handback (qa-developer, 2026-10-01)

**Root cause confirmed:** `_renderReports` drew the chart as 30 `<div>` bars with values only in `title`, and both totals tables as CSS grids of `<span>`.

**Fix** (commit `1ebce04`, `www/panel.js` Reports only, `www/i18n.js`):
- the bar container is `role="img"` with an `aria-label` summary: `reports.chart_summary` = "{total} min in the last 30 days, most on {date}: {n} min", or `reports.chart_none` = "No watering in the last 30 days." The axis labels under it are `aria-hidden` (the summary and table carry them). Bars keep their mouse `title`.
- the daily values are a real table in a collapsible "Daily values" `<details>` under the chart (closed by default, open state kept across the 5 s refresh). Product call I made on "how much text": only days with watering are listed (a 30-row table of zeros is noise); no table when there was none.
- per-zone and per-plan totals are `<table>` built by one `reportTable()` helper: `<th scope="col">` headers, zone / plan name as `<th scope="row">`, same columns, colours and numbers as before.
- skip-reason tiles unchanged (each tile already reads "number, label" in order).
New keys (17 languages): `reports.chart_summary`, `reports.chart_none`, `reports.chart_values`, `reports.col_day`.
