## Summary

"Water the front lawn for 10 minutes" (and German "Bewässere ... für N Minuten") starts the zone twice within a few milliseconds. The valve runs the right length, but every side effect is doubled: two `schedule_wizard_valve_started` events (automations listening to them fire twice), two "Opened ..." notifications, and a spurious `superseded` row in history and Recent activity. Hebrew, and "water <zone>" without minutes, start once.

## Steps to reproduce

1. Register a zone labelled `ENG front` (any switch / input_boolean).
2. Subscribe to `schedule_wizard_valve_started` (Developer tools > Events).
3. Assist (or WS `conversation/process`, language `en`): `water ENG front for 2 minutes`.
4. Repeat with language `de`: `bewässere ENG back für 1 minuten`.

## Expected

One run, one `valve_started` event and one `started` history row per command. Source: every other start path (service, webhook, panel, Hebrew voice) produces exactly one; README Events table: `valve_started` = "a zone started".

## Actual

Reproduced 3 times (2026-10-01 13:09, 13:10, 13:11):

```
en 'water ENG front for 2 minutes'     -> Watering ENG front for 2 minutes. | valve_started x 2
en 'water the ENG back for 1 minute'   -> Watering ENG back for 1 minutes.  | valve_started x 1
de 'bewässere ENG back für 1 minuten'  -> Bewässere ENG back für 1 Minuten. | valve_started x 2
he 'תשקה את ENG herbs 1 דקות'           -> ...                                | valve_started x 1
en 'water ENG herbs'                   -> Watering ENG herbs for 1 minutes. | valve_started x 1
```

History for the first command (newest first): `started`, `superseded`, `started`, all in the same second. Notifications: "Opened ENG front for 1 min (voice)" twice.

Event log and history rows above (WS capture). Recent activity shows the stray "superseded" row (bottom of the image, from the German command):

## Likely root cause

Proven from HA source plus the trace. The integration registers `run_zone_minutes` (`water [the] {zone} for {minutes} minute[s]`) and `run_zone` (`water [the] {zone}`) as separate conversation triggers. `{zone}` is a wildcard, so "ENG front for 2 minutes" also matches `run_zone`. HA's default agent (`components/conversation/default_agent.py`, `_handle_trigger_result`) runs the callback of **every** matched trigger, and the `run_zone` branch deliberately re-parses trailing minutes (`_TRAILING_MINUTES`), so both callbacks call `async_run_valve(zone, N)`; the second supersedes the first.

## Relevant files

- `custom_components/schedule_wizard/voice.py` (`SENTENCES`, `async_start`, `async_handle` run_zone branch)
- `tests/test_entities_voice.py` (`test_voice_end_to_end*` assert the speech and `is_on`, never the run count)

## Recommended remediation

One sentence must yield one `async_run_valve` call. Either register the run_zone and run_zone_minutes sentences of a language as a single trigger and decide by the slots, or make the `run_zone` callback return `None` (no action) when its `{zone}` text ends in a minutes phrase that `run_zone_minutes` also matches.

## Regression test

VOICE-01. In `test_voice_end_to_end` and the German parametrised case, capture `schedule_wizard_valve_started` and assert exactly one event, and no `superseded` history row.

## Handback (qa-developer, 2026-10-01): BUG-014 #53

**Reproduced:** with the real HA conversation agent in the test at baseline `01d6d10`, `water front lawn for 2 minutes` (en) and `bewässere Rasen für 1 Minuten` (de) each fired `schedule_wizard_valve_started` twice. With the article ("water the front lawn for 2 minutes") it fired once, as in the record.

**Root cause** (as in the record): `run_zone_minutes` and `run_zone` were separate conversation triggers. The `{zone}` wildcard of "water {zone}" also matched "front lawn for 2 minutes", and HA runs the callback of every trigger that matched.

**Fix** (commit `78f1b8c`, `voice.py`): in each language (en, de, he) the minutes sentences and the plain sentence are now one `run_zone` trigger. HA takes at most one match per trigger, so one sentence runs one callback. The handler uses the `{minutes}` slot when it is there. When the wildcard sentence matched instead, it still re-parses trailing minutes. Replies and the other commands are unchanged.
