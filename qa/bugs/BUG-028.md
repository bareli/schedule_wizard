## Summary

A run replaced by a new one on the same zone (Water now while it runs) is recorded as `superseded` with the minutes it really watered, but Reports (7d / 30d / total, daily chart) and the zone line ('N runs / M min last 7 days') count only `completed` and `cancelled`, so those minutes vanish from every total.

## Steps to reproduce

Water now 10 min on a zone, after 4 min Water now again; let the second run finish. Reports and the zone line count only the second run's minutes.

## Expected

The watered minutes of superseded rows are included in the minute totals.

## Actual

Server `per_valve_stats` and panel `_renderReports` filter `status in (completed, cancelled)`.

## Evidence

Not an interface picture: source and the regression test.

## Relevant files

custom_components/schedule_wizard/__init__.py (get_state stats), www/panel.js (`_renderReports`)

## Handback (qa-developer, 2026-10-01)

Fix commits `509425d` on `fix/v0.15.0-polish`. Full handback with recipe and environment: issue #89.

**Fix** (commit `509425d`, `__init__.py` get_state stats, `www/panel.js` `_renderReports`): a `superseded` row adds its watered minutes to the zone line's 7-day minutes and to Reports' 7 d / 30 d / total minutes and the daily chart. It does not add a run (the replacement run is counted). Only rows that carry `planned_min` count: rows written before 0.15.0 have no `planned_min` and hold the planned length rather than what watered (on 8188 one such row says 1440 min for a run replaced within seconds), so they stay out. Existing data is not changed.
