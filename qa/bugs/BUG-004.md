## Summary

In the add / edit zone dialog the switch or valve is chosen by clicking a row in a list of `<div>` elements. The rows have no role, no `tabindex` and no key handler, so a keyboard user cannot choose an entity. The search box and the list sit inside one `<label>`, so the search field's accessible name is the text of every entity row.

## Steps to reproduce

1. Zones tab, Tab to "Advanced: add a zone manually", Enter.
2. Tab from the zone name through the search box. Press Enter, Space and ArrowDown on and after the search box.
3. Read the focus order and the number of `.entity-row.selected` rows.
4. Read the accessible name of the search box.

## Expected

Each row is a keyboard-operable option (button, radio or listbox option) with a visible focus and selected state. Source: WCAG 2.1.1 (all functionality by keyboard).

## Actual

- No row ever receives focus (`tabIndex` -1, no `role`); Tab goes from the search box straight to "Minutes per run" (see screenshot). Enter, Space, ArrowDown select nothing (0 selected rows).
- Choosing the entity is required to save ("Pick a switch or valve"), so the dialog cannot be completed by keyboard, and "Edit zone" cannot change a zone's entity by keyboard.
- Mitigation: new zones can be added by keyboard through the setup wizard (checkbox list works), so adding is possible; changing the entity of an existing zone has no keyboard path.
- Accessible name of the search box, per the accessibility tree: `textbox "Switch or valve Front lawn input_boolean.zone_front input_boolean Front lawn ..."` (the whole picker is inside the `<label>`).

## Evidence

![picker rows with no focus stop; Tab skipped to Minutes per run](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/BUG-004-entity-picker-keyboard.png?raw=1)

Desktop 1280x760, light theme, English. After Tab from the search box, focus is on "Minutes per run" (the list was skipped); the list rows show no focus indicator. Code: `panel.js` L1531-1556 (`entity-row` div with a click handler only) and L1599 (`<label class="field">` wrapping `search` and `picker`).

## Likely root cause

Rows are plain divs with `click` listeners; the picker is nested in the label of the search input. Likely, not proven by a patch.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` (`_openValveModal`), CSS `.entity-row`.

## Recommended remediation

Render each row as `<button type="button" aria-pressed>` (or a radio group), give the list a name, move the picker out of the search label, keep the selected style plus `aria-pressed`. Focus ring via the existing `button:focus-visible` rule.

## Regression test
