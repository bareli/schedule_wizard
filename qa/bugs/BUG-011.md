## Summary

Related controls are visually grouped under a caption, but the caption is a `<span>`, not the group's label: the weekday chips, the "Send notifications to" and "Send notification when" checkboxes. The home status card's `role="progressbar"` has no name, and its `aria-valuenow` only changes on a re-render (every 5 s).

## Steps to reproduce

1. Zones, "+ Add time": read the tree of the days group. Settings: read the two checkbox groups. Start a zone from Home and read the progress bar.

## Expected

Groups have a name (`aria-labelledby` the caption, or `<fieldset><legend>`); a progressbar has an accessible name. Source: WCAG 1.3.1, 4.1.2.

## Actual

- Tree: `group:` (no name) containing `button "Mon" [pressed]`... in the schedule dialog; `aria-describedby` points to the error node, not a label. The wizard's days row has no `role=group` at all.
- Settings: checkboxes "persistent_notification", "Zone started", ... appear as a flat list; the captions "Send notifications to" / "Send notification when" are plain text.
- `progressbar` with no name; `aria-label` and `aria-labelledby` null; `aria-valuenow` "2" (stale between renders). The per-zone progress bar has no role.
- Not a defect: the weekday chips themselves are correctly `aria-pressed` toggle buttons; the toggle switches have role `switch` and `aria-checked`.

## Evidence

Evidence unavailable as an image: this is accessibility-tree structure with no visual difference. Tree output captured 2026-10-01 via `ariaSnapshot` and DOM attribute reads. Code: `panel.js` L1951 (`days` group), L2288 (wizard days), L2728-2748 (notify groups), L1038-1041 (progressbar).

## Likely root cause

Captions are `<span>` inside `<div class="field">`. Likely.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` (`_openScheduleModal`, `_openWizard`, `_renderSettings`, `_statusCard`).

## Recommended remediation

Give each caption an `id` and `aria-labelledby` on the group; add `role="group"` to the wizard's days row; name the progressbar from the zone and status text (existing keys) and update `aria-valuenow` in `_updateInPlace`.

## Regression test

A11Y-10: accessibility-tree check for named groups and progressbar. A pytest test can pin markup attributes only.
