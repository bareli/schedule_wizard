## Summary

The rain source picker (UX-011) lists Schedule Wizard's own entities under "Other sensors": `sensor.schedule_wizard_active_runs`, `..._next_schedule`, `..._water_used`, `binary_sensor.schedule_wizard_watering` and every zone's "time left" / "water used" sensor. `update_options` accepts them. Same spirit as #70 (own switches offered as zones). Found by the UX verifier on #66, reproduced here.

## Steps to reproduce

Settings > Skip watering when it rains, using: open the list. WS `{"type":"schedule_wizard/update_options","rain_entity":"sensor.schedule_wizard_active_runs"}`.

## Expected

The integration's own entities are not offered as a rain source, and the server refuses them ("rain_entity ... not found" like any other invalid source); an unchanged saved value still saves.

## Actual

Picker groups: `Other sensors: sensor.gynh_khvryt_time_left, sensor.gynh_khvryt_water_used, ..., binary_sensor.schedule_wizard_watering, sensor.schedule_wizard_water_used, sensor.schedule_wizard_active_runs, sensor.schedule_wizard_next_schedule`. update_options for `sensor.schedule_wizard_active_runs` and `binary_sensor.schedule_wizard_watering`: saved.

## Handback (qa-developer, 2026-10-01): BUG-030

**Fix** (`9c03ee5`, `__init__.py`, `www/panel.js` `_rainPicker` and the Settings save check):
- `get_state` returns `own_entities` (every entity of this integration, from the entity registry, the same set #70 uses for zones).
- The rain source list leaves them out; a source saved earlier that is one of them stays visible and selected (nothing changes silently).
- `update_options` refuses a new own entity: `rain_entity sensor.schedule_wizard_active_runs belongs to Schedule Wizard and cannot be a rain source` (the panel shows it under the field). An unchanged saved one still saves.
