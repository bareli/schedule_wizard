## Summary

All dialogs declare `role="dialog" aria-modal="true"`, but none implements the behaviour. Dialogs opened through `_showModal` (zone, plan, add / edit schedule) do not move focus into the dialog and have no accessible name. No dialog traps Tab, so focus walks onto the page behind the dark overlay, where the user cannot see it. Escape only works when focus is already inside. When any dialog closes, focus is lost to `<body>`. In the setup wizard the confirm step has no input or button in its body, so focus is lost there as well.

## Steps to reproduce

1. Zones tab, focus the first "+ Add time" button, press Enter.
2. Read the focus; press Tab until the first control inside the dialog is focused (count the presses).
3. Open it again and press Escape right after opening (focus still on the trigger).
4. Open the setup wizard (Home: "+ New watering plan"), pick 3 zones, press Next by keyboard to step 5 (Check), then press Tab 25 times.
5. Press Escape or Cancel in any dialog and read the focus.

## Expected

Opening moves focus into the dialog; Tab and Shift+Tab stay inside; Escape closes from anywhere; closing returns focus to the opener; the dialog has an accessible name. Source: WCAG 2.4.3 and 4.1.2; the dialogs declare `aria-modal="true"`, which promises an inert background.

## Actual

| Step | Result |
|---|---|
| Open "Add watering time" | focus stays on the trigger behind the overlay; `ariaSnapshot` shows `dialog:` with no name |
| Tab to the first dialog control | **8 presses** with 3 zones on the page; seven stops are controls hidden behind the overlay (see screenshot). Grows with page length |
| Escape right after opening | dialog stays open (focus is not inside) |
| Wizard step 5 | focus `BODY` (Next button destroyed, no field in the step); Tab then goes to the HA sidebar |
| Wizard, 25 Tabs | focus leaves the dialog (Cancel, body, HA sidebar, page tabs) and re-enters: no trap, background reachable |
| Any dialog closed | focus `BODY` |
| Run dialog (week view) | partly fine: focus moves in, Escape closes, named "Morning watering"; focus not restored |

Named correctly: wizard and run dialog (`aria-labelledby`). Unnamed: the three `_showModal` dialogs.

## Likely root cause

`_showModal` and the overlay handlers are minimal: no initial focus, no Tab handling, Escape bound to the overlay element only, `close()` just empties `#modal-root`, no stored opener. Likely, not proven by a patch.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` (`_showModal`, `_openRunModal`, `_openWizard`, each local `close`).

## Recommended remediation

One shared helper: remember `deepActiveElement()` on open; focus the first field (or the title with `tabindex="-1"`); trap Tab inside the dialog; bind Escape on the modal root; give `_showModal` an `aria-labelledby` on its `h3`; restore focus on close; in the wizard focus the step heading when the step has no field. Optionally make `#app` inert while a dialog is open. Interacts with BUG-002 (re-render must not break a restored focus).
