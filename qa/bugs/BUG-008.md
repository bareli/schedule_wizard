Declared standard: none in `qa/PROJECT.md`, WCAG 2.1 AA assumed. Tooling: Chromium 153 + Playwright 1.63.0 (accessibility tree). **No real screen reader was available.**

## Summary

In each zone row of the card the minutes field is a bare `<input type="number">` with no label, `aria-label` or `title`. A screen reader announces "spin button" with a value only. The Run and Stop buttons in every row are named just "Run" and "Stop".

## Steps to reproduce

1. Mount the card (a Lovelace dashboard was not edited; the module was imported into the dev page and `<schedule-wizard-card>` created with `setConfig({title: "Garden"})` and the live `hass`), three zones registered.
2. Read the accessibility tree of the card and the `aria-label` / `labels` of every input and button.

## Expected

Each input is labelled with the zone and purpose ("Front lawn, minutes"); buttons identify their zone. Source: WCAG 2.1 4.1.2, 3.3.2.

## Actual

Tree: `spinbutton: "10"`, `button "Run"`, `button "Stop"`, repeated three times. All 3 inputs: `aria-label` null, `labels.length` 0. A user tabbing the card hears the same three controls for each zone, and the card title is a `<div>`, not a heading.

## Evidence

![card with three unlabelled minutes boxes and identical Run / Stop buttons](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/BUG-008-card-unlabelled-inputs.png?raw=1)

Desktop 1280x900, light theme, English. The card was injected into the dev page by script (floating over the panel) because no dashboard was configured; the card code is unmodified. Code: `card.js` L368-372 (input), L388-399 (buttons).

## Likely root cause

`_valveRow` creates the input without a label. Likely.

## Relevant files

`custom_components/schedule_wizard/www/card.js` (`_valveRow`, `_activeRow`, `_soakRow`); strings `sched.duration` ("Minutes") already exist in `www/i18n.js`.

## Recommended remediation

`aria-label` on the input from existing keys plus the zone label (for example `sched.duration` + label); `aria-label` on Run / Stop that includes the zone; render the card title as a heading. See also BUG-002 (focus loss in the card) and UX-007 (names).

## Regression test

A11Y-07: accessibility-tree check on a mounted card. A pytest test can only pin i18n keys.

## Fix prompt

Fix BUG-008 in Schedule Wizard. Problem: card.js `_valveRow` minutes inputs have no accessible name; Run / Stop buttons are identical per zone. Expected: names include the zone (WCAG 4.1.2, 3.3.2), reuse existing i18n keys where possible, keep 17 languages in sync. Reproduce: import the card into the HA page, read the accessibility tree.

## Handback (qa-developer, 2026-10-01)

**Root cause confirmed:** `card.js` `_valveRow` built a bare `<input type="number">` and two buttons whose only text was "Run" / "Stop"; `_activeRow` / `_soakRow` the same Stop; the title was a `<span>` in a `<div>`.

**Fix** (commit `1ebce04`, `www/card.js` + `www/i18n.js`):
- minutes field `aria-label` = `card.minutes_for` ("Front lawn: minutes", de "Front lawn: Minuten", he "Front lawn: דקות"), and a visible unit next to it via the existing `unit.min` template wrapped in a `<label>`;
- every button named `card.action_for` = "{action}: {zone}" with the visible text first (WCAG 2.5.3): "Water now: Front lawn", "Stop watering: Front lawn". All Stop buttons go through one `_stopButton()`;
- the title is an `<h2>` (also on the load-failed card);
- words aligned with the panel under #71 (Water now / Stop watering instead of Run / Stop).
New keys in all 17 languages: `card.minutes_for`, `card.action_for`.
