## Steps to reproduce

1. Open the editor for a schedule that clashes (`_openScheduleModal` for "Overlap test"; the amber box shows "Waters at the same time as Morning lawn (Sun 6:00 AM)." and a "Move to 6:35 AM" button).
2. Tab to "Move to 6:35 AM" (focus ring visible), press Enter.

## Expected

Focus stays in the dialog on a sensible control (the time field that just changed, or the box), and the result is announced.

## Actual

The button is removed when the conflict box re-renders empty (`conflictBox.innerHTML = ""`). `document.activeElement` becomes BODY (the dialog contains no focus). The next Tab lands on the "Repeat" select near the top of the dialog, Shift+Tab goes to Save. The box clears silently: a screen reader user hears nothing about the conflict being resolved.

## Fix

In the Move to handler call `timeInput.focus()` after setting the value (or focus the `aria-live` wrapper), and write a short status ("Moved to 6:35 AM, no overlap") into the live region instead of just clearing it.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` (`runConflictCheck`, Move to onClick, around line 3215-3230).
