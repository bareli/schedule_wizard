## Summary

In the zone editor, "Minutes per run" of `0` or an empty field is accepted, the dialog closes with "Done", and the zone is stored with **10** minutes (whatever it was before, here 45). The user typed 0 and gets 10-minute runs from Water now, voice and calendar defaults. Out-of-range values (`2000`, `-5`) do reach the server and are rejected, but only as a raw English server message in a toast ("Failed to perform the action schedule_wizard/add_valve. value must be at most 1440 at 'default_duration_minutes'"); there is no inline message. The schedule editor in 0.14.0 got inline errors; the zone editor did not.

## Steps to reproduce

1. Zones > a zone with 45 min > Edit zone.
2. Minutes per run: `0` (or clear the field) > Save.
3. Dialog closes with "Done"; the zone line now reads "10 min per run". `get_state` shows `default_duration_min: 10`.
4. Edit again, `2000` > Save: toast with the raw server text, dialog stays, no inline error.

## Expected

0, empty and values outside 1 to 1440 are refused in the dialog with an inline message next to the field (as the schedule editor does since 0.14.0), and nothing is saved. Source: input `min="1" max="1440"`; server schema `vol.Range(min=1, max=1440)`; `qa/PROJECT.md` *Fix constraints* "client + server validation".

## Actual

Reproduced twice (13:30, 13:33):

```
zone minutes "0"    modal open: 0 inline: [] toast: Done                     stored: 10

```

## Evidence

Zone "QAE five" after entering 0: "10 min per run" (it had 45; its last run line still says 45 min):

![Zone after saving 0 minutes shows 10 min per run](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/BUG-016-zone-minutes-0-saved-as-10.png?raw=1)

## Likely root cause

`www/panel.js` `_openValveModal`: `durInput.addEventListener("input", () => { duration = parseInt(durInput.value, 10) || 10; })`. `0` and `NaN` are falsy, so they become 10; the save handler never checks the range. Same `|| 10` pattern in `_openScheduleModal` for the schedule minutes (`durInput`), worth checking in the same fix.

## Relevant files

- `custom_components/schedule_wizard/www/panel.js` (`_openValveModal`, `_openScheduleModal`)
- `custom_components/schedule_wizard/www/i18n.js` (new error string, 17 languages)

## Recommended remediation

Read the raw field value on Save; if it is not an integer 1 to 1440, show an inline `field-error` under Minutes per run (same pattern and ids/aria as `sw-sched-interval-err`), keep the dialog open, and do not call the service. Remove the `|| 10` fallback. Related: UX-005 (validation only in toasts) and BUG-012 (toast off-screen); this record is the silent wrong value, which neither covers.
