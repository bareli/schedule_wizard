Declared standard: none in `qa/PROJECT.md`, WCAG 2.1 AA assumed. Tooling: Chromium 153 + Playwright 1.63.0; ratios computed from computed colours over the composited ancestor backgrounds.

## Summary

The panel and card use the Home Assistant theme tokens directly as text and background colours. With HA's default theme (`--primary-color` `#009ac7`, `--success-color` `#43a047`, `--error-color` `#db4437`) most coloured text fails the 4.5:1 text threshold.

## Steps to reproduce

1. Open Home, Zones and a dialog (Zones: "+ Add time") in the light and the dark theme.
2. Read computed `color` and the composited background of each element in the table.

## Expected

4.5:1 for text under 18.66 px regular / 14 pt bold (1.4.3). Source: WCAG 2.1 AA.

## Actual

| Element | Size | Light | Dark |
|---|---|---|---|
| `.btn.primary` white on `#009ac7` (Water now, Save, Add zones) | 14px | **3.26** | **3.26** |
| `.day-chip[aria-pressed=true]` white on `#009ac7` | 13px | **3.26** | **3.26** |
| `.tab.active` `#009ac7` on `#fafafa` | 14px | **3.12** | 5.80 |
| `.btn.ghost` / `.link-btn` `#009ac7` on `#fafafa` / `#fff` | 13-14px | **3.12 / 3.26** | 5.80 / 5.23 |
| `.pill.ok` "All good" `#43a047` on `rgb(220,241,228)` | 12px | **2.79** | **4.24** |
| `.btn.danger` "Delete" `#db4437` on white / dark card | 12px | **4.29** | **3.97** |
| `.pill.run` primary on its tint (not separately computed; same colour pair as above) | 12px | below 3.2 expected | not computed |
| Passes: muted text `#5e5e5e` on white 6.48 (dark 6.13), main text 18.4 | | | |

1.4.11 (3:1 for UI components): the button fills are at 3.26:1 against white and pass; this record is only about text.

## Evidence

![primary colour pairs on Home, light theme](https://github.com/bareli/schedule_wizard/blob/main/qa/evidence/BUG-006-primary-colour-contrast-light.png?raw=1)

Desktop 1280x900, light theme, English, default HA theme, a zone watering. White text on the blue "Water now" buttons, blue "Skip day" / "+ New watering plan" text, blue tab label.

Note: the colours come from the active HA theme. The failures are measured on the default theme that ships with HA 2026.9; a custom theme with darker tokens would pass. The panel has no guard (it always puts white on `--primary-color`).

## Likely root cause

`.btn.primary`, `.day-chip`, `.tab.active`, `.btn.ghost`, `.link-btn`, `.pill.ok`, `.btn.danger` take theme tokens directly; the card has the same pattern (`button.run`, `button.stop`). Likely.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` STYLES; `www/card.js` CARD_STYLES.

## Recommended remediation

Product call: derive text colours that reach 4.5:1 (for example `color-mix` the theme colour toward the text colour, or a darker accent for text), or put dark text on the primary fill when the theme colour is light. Check light and dark.

## Regression test

A11Y-05: browser contrast measurement of the listed selectors under both themes. A pytest check cannot compute the rendered ratio.
