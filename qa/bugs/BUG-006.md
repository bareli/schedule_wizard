## Summary

The panel and card use the Home Assistant theme tokens directly as text and background colours. With HA's default theme (`--primary-color` `#009ac7`, `--success-color` `#43a047`, `--error-color` `#db4437`) most coloured text fails the 4.5:1 text threshold.

## Steps to reproduce

1. Open Home, Zones and a dialog (Zones: "+ Add time") in the light and the dark theme.
2. Read computed `color` and the composited background of each element in the table.

## Expected

4.5:1 for text under 18.66 px regular / 14 pt bold (1.4.3). Source: WCAG 2.1 AA.

## Likely root cause

`.btn.primary`, `.day-chip`, `.tab.active`, `.btn.ghost`, `.link-btn`, `.pill.ok`, `.btn.danger` take theme tokens directly; the card has the same pattern (`button.run`, `button.stop`). Likely.

## Relevant files

`custom_components/schedule_wizard/www/panel.js` STYLES; `www/card.js` CARD_STYLES.

## Recommended remediation

Product call: derive text colours that reach 4.5:1 (for example `color-mix` the theme colour toward the text colour, or a darker accent for text), or put dark text on the primary fill when the theme colour is light. Check light and dark.

## Handback (qa-developer, 2026-10-01)

**Root cause confirmed:** the panel and card put HA theme tokens directly into text colour (`--primary-color`, `--success-color`, `--error-color`) and white text on `--primary-color`.

**Fix** (commit `3ae4dc7`, `www/panel.js` STYLES, `www/card.js` CARD_STYLES): derived tokens instead of the raw theme colours. Text: `--sw-<primary|success|danger|warn>-text: color-mix(in srgb, <theme colour> 65 / 60 / 70 / 40 %, var(--sw-text))`, i.e. toward the theme's own text colour, so it darkens in a light theme and lightens in a dark one. Fills under white text: `--sw-<primary|success|danger>-fill: color-mix(in srgb, <theme colour> 75 / 75 / 80 %, #000)`. Used by the active tab, ghost and link buttons, pills, badges, week tags, danger outline, field errors, inline report colours (text) and primary buttons, day chips, switch on, domain badge, toasts, alert banner, danger hover (fills). Borders, focus ring and progress bars keep the theme colour (non-text, at or above 3:1). Without `color-mix` support (`@supports`) the tokens fall back to the raw theme colours, i.e. the old look. The card gets the same three tokens it needs.
